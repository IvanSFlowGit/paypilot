Failed payment recovery with fixed rules and human approval

PayPilot decides what to do about a failed payment from a fixed rules table. A language model writes the wording only. Every decision records the rule that applied, and nothing is sent until a person approves it. The demo below runs one failed payment through the process.

Why not ask Claude to do this on a spreadsheet? Someone has to ask each time, and the answer can differ between runs. PayPilot applies the same rules to every failed payment and records which rule produced each decision. The FAQ below has the longer answer.

How it works

A failed-payment event flows through a typed LangGraph state machine. Each node enriches a shared state and hands it on.

Retrieve + assess + diagnose

Loads the customer record, pulls relevant snippets from the dunning playbook (RAG), and scores churn risk from the attempt count and recent failures - then produces a short, grounded diagnosis of why the charge failed: committed templates by default, an LLM only when live drafting is enabled.

Decide + schedule

The retry action and cadence come from a fixed rules table keyed on the failure code - not an LLM - and tighten automatically when churn risk is high. A schedule node then pins the concrete next-retry time, ready for a scheduler. Stable and unit-testable.

Draft the email

A warm, on-brand dunning email is written the same way - committed copy by default, LLM when enabled, with one clear call to action, grounded in the playbook's tone guidance.

FAQ

The questions a hiring manager or a curious engineer usually asks.

What is PayPilot?

PayPilot recovers failed subscription payments. A fixed rules table decides what happens next and a language model only writes the wording. Every decision stores the rule that applied, and nothing is sent until a person approves it. It has no paying clients yet.

How does PayPilot decide the retry strategy?

The retry action and cadence come from a deterministic rules table keyed on the failure code, not the language model, so the policy is stable and unit-testable. When churn risk is high, the cadence tightens automatically. A code the table does not list lands on a row named default, and the record says default fired.

What does PayPilot refuse to do?

It refuses to send a message unless sending is switched on, a person has approved it and the recipient is on an allowlist; an empty allowlist means nobody. A drafted message that carries a link it did not sanction, or anything shaped like a secret, is replaced with fixed copy, and a send that fails the same check is refused. It refuses to return a decision it could not record. Refusals are stored in separate places today, not in one ledger.

Does the live demo need an API key?

No. With no OpenAI key set, PayPilot runs a deterministic mock mode using grounded playbook templates and a lexical retriever, so the demo works offline, free, and with no signup. Adding an API key alone changes nothing: live drafting also needs PAYPILOT_LLM_DRAFT=1.

Does PayPilot handle ACH returns as well as card declines?

The dunning agent handles card and subscription charge failures: its tables are card decline codes and Recharge error types. ACH is separate. PayPilot publishes a deterministic decision table for returned ACH debits at /ach-returns, where 17 return codes sort into 5 decisions, and that table is not wired into the dunning agent. Saying PayPilot handles ACH would overstate it; it publishes a decision table for ACH.

What is the ACH return-code decision table?

Seventeen ACH return codes sorted into five decisions, because there are five answers to the one question that decides what happens next: what has to change before the debit can exist again. Nothing, the account details, their instruction, our own entry, or nothing ever will. Any code the table does not list falls through to the conservative row, where nothing automatic happens, and the answer says it fell through rather than matched.

Can an agent call PayPilot over MCP?

Yes. The ACH decision table ships as an MCP server with three read-only tools: lookup_return_code, list_decisions and explain. The agent asks, the table decides, and the answer carries which rule fired, so no model sits in the decision path. Nothing writes and nothing reaches the network, declared per tool as read_only_hint and open_world_hint false.

What technology does PayPilot use?

A seven-node LangGraph state machine with retrieval-augmented generation (RAG) over a dunning playbook, served through a FastAPI endpoint. It is written in Python 3.11 and runs its full test and evaluation suite offline.

How does PayPilot measure recovered revenue?

Every response quantifies the amount at risk, the recovery likelihood, the expected recovered value, and the annual revenue at risk if the customer churns. Recovery likelihood is an illustrative constant, not a measured rate.

Does PayPilot send emails on its own, and does it work with Gmail or Proton Mail?

No. By default PayPilot sends nothing and a person approves every message. It writes the proposed message and either emails the approver a link, or puts it in your own Drafts folder in Gmail, or in any IMAP mailbox such as Proton Mail through Proton Mail Bridge, so you read it there and press Send yourself. In those modes it creates, reads and deletes only its own drafts. Delivery through Resend happens only when sending is switched on, a person approved that message, and the recipient is on an allowlist.

What happens when a customer replies to a dunning email?

The automated sequence for that invoice stops, so nothing talks over the customer and a person answers instead. Replies are noticed in two ways: an endpoint that a helpdesk rule or a person can call, and an opt-in watcher that reads a mailbox read-only (IMAP, Gmail or Microsoft Graph) and recognises a real reply by the invoice reference in each email. Out-of-office and bounce messages never stop it, and a bounce is reported as an undelivered reminder. Clearing the hold resumes the sequence at the right step. A reply with a large attachment is still caught by its headers. It has been tested on synthetic mail. A read-only dry run against a real mailbox has read its mail without error, but no real customer reply has been through it yet.

What does PayPilot do when a customer says they have already paid?

It reads the reply, checks the claim against a bank feed where one is connected, and drafts one reply for a person to approve. It never says a payment was received unless a credit carrying the invoice number is found, and a pending credit is described as pending. With no bank feed, or a feed it cannot reach, the reply says so and goes to a person. Disputes, double charges, cancellations, shortfalls and requests to stop contact are routed to a person with a holding reply that admits nothing. No model runs, the customer's own words are never copied into the reply, and nothing is sent. The bank feed is simulated in the public demo.

How is PayPilot different from using Claude in Excel on the same data?

Claude in Excel is a general assistant: a person asks, a model reads the workbook and answers or edits. That is useful for one-off analysis, and Anthropic's own documentation says the add-in sends the content it reads to Anthropic, that files from outside sources can carry hidden instructions, and that it should only be used on trusted spreadsheets. PayPilot is a fixed procedure. Which invoice gets which label, and whether chasing stops, is decided by written rules with no model in that step, so the same ledger gives the same answer every run and a customer's email cannot change the decision. The wording step masks names and addresses before it leaves, nothing is sent without a person approving it, and every outbound connection is listed and pinned by a test.

How does PayPilot handle security and customer data?

It collects as little as it can. Customer names are replaced with salted hashes before the rules run, the reply reader and the decision step run no model, and the only text that reaches a model is a wording task with names and addresses masked. Bank, Xero, QuickBooks, Sage and mailbox access is read-only. Nothing is sent without a person approving it, and a request to stop contact outranks every other rule. Hostile input is treated as data: control characters are refused, quoted text is ignored and the customer's words are never copied into a reply. It has not had an external penetration test.

Does PayPilot stop chasing while a payment is on its way?

Yes, where a bank feed shows a credit carrying the invoice number. A pending credit pauses the chase for 3 business days and a booked credit for 5, then the pause ends, so a payment that never arrives is chased again. An amount-only match does not pause anything. Those two periods are starting values, not measured figures, there is no bank holiday calendar, and this has only run on invented bank data.

Can PayPilot read Xero, QuickBooks, Sage, a bank feed or an Outlook mailbox?

The readers are built and have only run on invented data. Xero and Sage can be limited to read-only scopes, and the code refuses any write scope. QuickBooks Online has no read-only scope, so only PayPilot's own client keeps it read-only: it allows a single kind of GET request and refuses everything else. The Outlook reader asks for Mail.Read only and keeps a message only when it matches a known invoice. The bank feed reader parses a standard bank response offline and has no live connection. A signed data processing agreement and a per-client credential come before any live use.

Is every follow-up dunning email the same as the first?

No. The second email is a short reminder and the email sent when the business's own cap is reached says plainly that it is the last one. It only says last when the cap makes that true, so a business that allows five emails does not get a false last reminder at three. Every failure code has its own wording at each step, and a customer name or plan that contains template braces falls back to a safe default instead of showing in the email. The copy is committed and read by a person, and a test grid of 640 synthetic cases checks every code at every step.

Is PayPilot GDPR and SOC2-ready?

Yes, with controls evidenced in code: personal data is masked before the model and is not stored in the ledger, scripted and tested jobs export and erase a customer's data end to end, records auto-expire on a configurable retention window, an append-only audit log records every money and auth event, and webhooks and admin routes are authenticated. It is also EU AI Act limited-risk with a configurable AI-assistance disclosure on generated emails. SOC2-ready means the controls are built and evidenced, not that a certification audit has been run.

Can PayPilot label unpaid invoices that are overdue?

Yes, as a separate layer from the card decline table. It reads a CSV export plus a few facts you supply (chases sent, replies received, a dispute flag, a promised-by date) and returns one of five labels or UNKNOWN, with the rule that fired. It is arithmetic and flags only, with no model, and an untracked reply count is UNKNOWN rather than zero. Readers for Xero, QuickBooks Online and Sage invoices exist and have only run on invented data, as has the label layer itself; none has seen a real business's records.

Does customer data leave the EU?

By default no model is called at all: the wording comes from committed, human-reviewed copy that fixed rules fill in. If live drafting is switched on, the only text sent to a model is a wording task with names and addresses masked, and it goes to OpenAI's API. If an OpenAI key is set, a short query built from the failure code and plan name is also sent to OpenAI's embeddings API. No region is configured for either, so there is no EU-only guarantee. The app runs in the London region on Fly.io. A deployment that must keep data in the EU leaves both switches off.

Can PayPilot read a rent or service charge ledger from a property system?

It reads a CSV export of the ledger, with the item named as rent or service charge in the draft. UK exports often use day-first dates and amounts such as £1,250.00, so the profile states which date format and amount style the file uses. Nothing is detected, because 02/01/2026 is two different days depending on the system. Negatives, credits and malformed amounts are refused row by row. A tenant who says they cannot pay, reports a repair or is waiting for a benefit payment gets a holding reply and a person decides. No property management system is connected, it has only run on invented exports, and rent arrears rules that depend on jurisdiction and tenancy are not encoded.

Does PayPilot work with Unit or another ACH processor?

There is a translation from Unit's published list of return reasons to ACH codes, and an offline tool that replays a saved delivery through the ACH table. A receiver checks Unit's signature, decides each returned payment from that table and records it, and sends and retries nothing. A reason that is missing from the event is held for a person and never guessed; an admin can then supply the code through a token-gated route, which appends the table's decision beside the hold. Unit's support has said in writing that the return code is on the event's reason attribute, but nothing here has seen a live returned-payment event. Any other processor can call the decision API with an invoice id and a failure code.

Can several clients share one PayPilot deployment?

Yes, or each client can have their own. Separate deployments, each with its own database and keys, give the strongest separation and remain available. One deployment can also serve several clients: every ledger row carries a tenant, every query is scoped to it, each client has its own webhook address and signing secret (stored encrypted and never readable back), access is by per-client tokens with roles, and a suspended client is never mailed. That separation is enforced in the application and checked by tests. An optional Postgres backend adds database row-level security, checked against a real Postgres 15, and by default every client shares one database role there; a per-client database login mode exists whose escape attempts fail on a real Postgres 15 test cluster, but it has not carried production traffic. A client who needs the strongest separation is given their own deployment. No production run has yet served more than one client.
