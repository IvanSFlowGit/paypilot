PayPilot - Compliance

How PayPilot is built and governed for the EU AI Act, GDPR and secure-by-design operation.
EU AI Act aligned - Limited risk, human-in-the-loop

1. Risk classification

PayPilot is an AI-assisted content and decision-support tool that drafts payment-recovery actions for a subscription a customer already agreed to. It does not take autonomous action on a person, score individuals for access to essential services, or perform biometric, employment or law-enforcement functions. Under the EU AI Act it is a limited-risk system, subject to transparency obligations (Art. 50), which it meets.

2. Human oversight (Art. 14 spirit)

The agent drafts - a diagnosis, a retry strategy and a recovery email. A human reviews and approves before anything is sent. Nothing reaches a customer autonomously. The operator can override or discard any output.

3. Transparency (Art. 50)

Recovery emails are clearly AI-generated and human-approved. The system's purpose, inputs and limitations are documented in the repository and summarised for answer engines in /llms.txt.

4. Privacy-Enhancing Technologies (PETs)

  • Data minimisation - only the fields needed to diagnose a failed charge (amount, failure code, plan, retry history). No browsing, location or special-category data.
  • No unnecessary retention - processing is stateless per request; PayPilot stores no personal data of its own.
  • Synthetic data in the demo - the public demo and the full test suite run on synthetic fixtures with no real personal data, entirely offline (no API key, no network).
  • Encryption in transit - all traffic over TLS.

5. Governance

  • Documented purpose, risk tier and limitations (this page + the repository).
  • Deterministic, grounded design - retrieval-augmented over a written dunning playbook, so recommendations trace to a source.
  • Versioned and tested - a 7-node LangGraph state machine with a full offline test suite and evaluation harness.

6. Security (secure by design)

  • Runs as a non-root user in a container; code and data are read-only at runtime.
  • No secrets in code; least-privilege configuration.
  • Tests run with no network and no credentials, so CI cannot leak data.

7. GDPR

When a merchant deploys PayPilot on real data, the lawful basis is legitimate interest (recovering a payment the customer agreed to owe). The deploying merchant remains the data controller and supports data-subject rights; PayPilot is a stateless processor that retains nothing.
